daily-stock

Roadmap 與 Phase 1 目標

AI 台股盤後分析研究工具。輸入公開資料（大盤、三大法人籌碼、個股日K）+ 財金新聞，產出白話解讀 + 術語教學 + 可回測的因子訊號研究。定位是理解 + 研究——訊號來自可回測的規則引擎與真實因子打分，LLM 只負責解讀「為什麼」與教學，不憑空喊單。

範圍與定位聲明

本專案僅供個人學習與回測研究使用，不對外提供服務。所有產出均為研究與教育性質，非投資建議，不構成任何買賣邀約。開發者不對使用本工具所生之投資決策負責。

一、設計原則

1
數字防幻覺（輸入端）
股價 / EPS / 買賣超一律從 API 取真值餵給 LLM。LLM 只解讀，數字由程式代入模板——想寫錯都寫不了。
2
輸出忠實度驗證（輸出端）
eval set 檢查解讀是否忠於原始數據。改 prompt、換 provider 必重跑，CI 當 merge gate。
3
Provider 可切換
llm.Provider 與 embed.EmbeddingProvider 雙介面，Claude / Gemini / 地端 Ollama config 一行切，上層零改動。
4
訊號可回測
規則要能對歷史資料 walk-forward 回測（避開 look-ahead / survivorship / overfitting），站不住就不出訊號。
5
先計劃再動手
每個 phase 有獨立 plan doc，看過才實作。

Phase 3 新聞 RAG + 個股問答 agent AI 練習主菜
新聞 embedding（pgvector）+ hybrid 檢索 + LLM tool-use agent + trace + agent eval。
Phase 4 Web dashboard + 基本容器化 未開始
Go API（REST + SSE streaming）+ React/TS 前端四頁 + Dockerfile/compose + CI eval gate；雲端部署延後。
Phase 2'' 回測完整版 想衝量化深度時
多因子、調參、交易成本模型、survivorship 處理。
順序理由

學習目標是 AI 應用（RAG / embedding / agent / eval harness），這些全部在 Phase 3，故升為主菜；Phase 2 是量化工程、AI 含量最低，降為極簡 timebox 版，保住「回測站得住才出訊號」的原則即可。

Phase 1.5 插隊的理由：專案的第一優先已從「求職作品集」改為「自己每天實際使用的工具」。驗收標準隨之從「DoD 打勾」變成「我明天會不會打開它」，最痛的需求變成「我手上這 20 檔今天怎麼了」——而那不在任何既有 phase 裡。回測（2'）與 RAG/agent（3）順序不變，只是往後移。

六、Phase 1 目標

全自動資料管線 + LLM 白話摘要：排程器每日自動抓 TWSE 大盤指數、三大法人買賣超、個股日K 與財金新聞，直接落地 PostgreSQL（不經手動、不落散裝檔案），再由 LLM 生成白話解讀 + 術語註解。不產生任何買賣訊號。

同時建立三個地基，後面每個 phase 都踩在上面：

1
Postgres 為唯一真相來源
day 1 就用 pgvector image，Phase 3 加向量欄位零遷移；Phase 2 回測直接查歷史表。
2
Provider 可切換
llm.Provider 介面，Claude / Gemini / Ollama config 一行切。
3
輸出忠實度 eval
把 LLM 當「不完全可信的元件」來管理的驗證機制。
TWSE OpenAPI 的關鍵現實

多數 OpenAPI 端點只回最新交易日、沒有歷史查詢參數。所以「每天準時抓、抓了就存」不是優化而是必需——歷史資料是自己日積月累存出來的。這正是 day 1 就上 Postgres 的理由；漏抓一天等於那天要走 backfill 路徑補。

（Phase 1.5 補充修正：www.twse.com.tw 的 RWD 端點帶 date 參數可取歷史，backfill 走的就是這條路徑。）

產出範例

📊 2026-08-07 盤後摘要
大盤：加權指數收 22,150 點，漲 85 點（+0.39%） → 白話：今天大盤小漲，屬於溫和整理格局，沒有明顯方向性表態。
三大法人：外資買超 32 億元，投信賣超 5 億元 → 白話：外資站買方，是短線偏多的訊號之一，但投信同步賣超，顯示法人對後市看法不完全一致。
【術語小教室】
買超／賣超：指法人當日買進金額扣掉賣出金額後的淨額。
⚠️ 以上內容僅供學習與理解市場動態使用，非投資建議。

防幻覺機制：數字不讓 LLM 寫

LLM 輸出：「外資買超 {foreign_net} 億元，顯示…」   ← 只准寫佔位符
渲染層：  程式把 pg 查出的真值填進 {foreign_net}    ← 數字永遠是真的
驗證：    佔位符必須 ∈ 已知欄位集，否則 reject 重生成

模板方案讓「數字錯」被結構性消滅，eval 因此只需聚焦剩下兩類問題：方向曲解（買超 32 億被解讀成「賣壓沉重」，用 LLM-as-judge + rubric）與紀律違規（出現建議性字眼，用黑名單程式斷言）。

七、Phase 1 完成定義（DoD）

  • ✓docker compose up -d 起 pg(pgvector) + redis，healthcheck 過
  • ✓goose migrations 建齊全部表（含 eval_runs / eval_case_results）
  • ✓daily-stock schedule 長駐：平日 17:30 自動抓、18:30 自動生成摘要、每 30 分鐘抓新聞，全程無手動
  • ✓冪等：同日重跑 ingest 任意次，各表資料不重複不變質
  • ✓raw_payloads 有原始 payload，daily-stock reparse 可重放解析
  • ✓daily-stock backfill 可回補個股歷史（帶 rate limit）
  • ✓出站呼叫走 rediskit rate limit；排程 job 有 rediskit lock
  • ✓摘要走模板代入，數字非 LLM 生成；summaries 落地
  • ✓llm.Provider 跑通（Anthropic / Gemini / Ollama 三個 adapter）
  • ✓術語教學 ≥ 10 詞彙（目前 12）
  • ✓eval set ≥ 20 組，daily-stock eval 可重跑，結果落 eval_runs
  • ○internal/store testcontainers 整合測試（upsert 冪等、migration 可重放）→ 順延至 Phase 1.5 週 3
  • ○README 附 demo 輸出與排程 log 截圖 → 順延至 Phase 1.5 週 3

八、風險與紀律

面向紀律
免責 所有輸出（含前端每頁）標「非投資建議，僅供理解與學習研究使用」；定位為個人研究工具，不對外提供訊號服務。
版權 新聞優先官方 RSS / API，爬蟲遵守 robots.txt，不整篇轉存展示。
回測前不出訊號 Phase 1 只做白話摘要、Phase 1.5 只做描述性統計；訊號需通過 walk-forward 驗證才納入輸出，且每次顯示「歷史回測不保證未來」。
對外請求 rediskit RateLimiter 包所有 TWSE / RSS 出站呼叫；backfill 尤其要慢——被 ban 整條管線停擺。
地端模型限制 Ollama 在 tool-use（Phase 3）能力較弱，需支援 function calling 的模型（Qwen / Llama 3.1+）或 fallback JSON 模式，品質作為對照組。

九、已知限制（誠實揭露）

限制說明
系統性風險未納入訊號未考慮大盤系統性風險——系統性下跌時個股因子可能全數失真。
回測樣本受限受限免費 API 的歷史區間，樣本外驗證力有限。
survivorship bias無歷史成分股資料，以「大型權值股 + 上市年限門檻」折衷並誠實揭露。
eval 覆蓋率eval set 涵蓋常見情境，非全面驗證。
檢索未加 reranker現階段資料量不需要。
