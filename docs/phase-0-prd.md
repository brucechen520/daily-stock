# Phase 0 — 產品需求規格書（PRD）

> 本文件回答 **What & Why**（產品是什麼、為誰、有哪些功能、怎樣算做完）。
> 工程實作的 **How & When**（技術選型、開發順序）見 [ROADMAP.md](ROADMAP.md) 與各 phase 文件。
> 產品形態：**面向一般使用者（client）的台股盤後理解與學習產品**（web app + 每日推播）。
>
> 📌 **現狀聲明**：本文件為「產品化情境」下的規格設計演練，**現階段本專案未對外提供服務**，實際定位仍為個人學習與研究工具（見 README）。若未來決定對外，需先完成 §1.1 之法遵行動項並更新全 repo 定位聲明。

## 1. 產品定位

**一句話**：每天盤後，用白話幫使用者看懂台股今天發生什麼、就地學會投資術語，並提供「算法透明、經過回測」的因子數據研究——一個**教育與資訊整理**產品。

**電梯句（對 client）**：「收盤後 5 分鐘，看懂今天的台股。」

### 1.1 法遵紅線（產品範圍的第一決策，不是附註）

台灣《證券投資信託及顧問法》對「向不特定人提供證券投資建議」有規範。本產品是**對外服務**，因此：

| 內容 | 能不能對 client 提供 | 說明 |
| --- | --- | --- |
| 客觀數據彙整（行情/籌碼/新聞）| ✅ 可 | 公開資訊整理 |
| 白話解讀「發生了什麼現象」 | ✅ 可 | 教育性質，不涉及應否買賣 |
| 術語教學 | ✅ 可 | 教育性質 |
| 因子數據與歷史統計展示 | ✅ 可 | 呈現客觀計算結果與回測統計 |
| **多空分級標籤（偏多/偏空）** | ⚠️ **feature flag，預設關** | 系統性產出方向性標籤給不特定人＝模糊地帶，法遵評估通過前不對 client 開放；期間僅供內部研究 |
| 個股買賣建議、目標價 | ❌ 永不 | 明確紅線 |

- 全產品所有輸出載明「教育與資訊整理用途，非投資建議」。
- 問答助手被問「該不該買」一律觸發拒絕模板。
- **行動項**：正式對外前完成法遵諮詢；在此之前對外版本關閉分級標籤，只展示因子數據。

## 2. 目標使用者與痛點

| Persona | 描述 | 痛點 | 對應模組 |
| --- | --- | --- | --- |
| **投資新手**（主要）| 剛開始關注台股的上班族/學生，看得懂新聞看不懂術語 | 盤後資訊散落各處；術語密度高，查一個詞斷一次閱讀；不知道每天該看什麼 | M2 M3 M8 |
| **忙碌上班族**（主要）| 有投資但沒時間盯盤 | 收盤後想快速掌握當天重點與自己關注的股票 | M2 M8 M9 |
| **自學量化的研究者**（次要）| 想驗證「外資連買會漲」這類說法 | 網路訊號黑箱不可驗證 | M4 M5 |

## 3. 非目標（明確不做）

- ❌ 即時報價 / 盤中看盤（定位是「盤後理解」，也避開行情授權費）
- ❌ 買賣建議、目標價、進出場點位（法遵紅線）
- ❌ 下單、券商整合
- ❌ 台股以外市場
- ❌ 社群功能（留言/追蹤/分享名單）——先做好單人體驗

## 5. 模組規格

### M1 市場資料中心（平台底座）

**目標**：client 零感知，資料每天自動到位；歷史資料日積月累。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-1.1 | 平日盤後自動抓大盤/三大法人/全市場個股日K | 17:30 觸發、18:00 前完成；非交易日自動跳過 |
| FR-1.2 | 財金新聞自動抓取 | 每 30 分鐘；同篇不重複 |
| FR-1.3 | 抓取冪等 | 同日重跑任意次資料不重複 |
| FR-1.4 | 歷史回補 | 可回補指定個股/區間，受限速保護 |
| FR-1.5 | 失敗可觀察 | 重試 3 次 + 告警 log；資料缺漏隔日可補 |
| FR-1.6 | 資料延遲承諾 | 對 client 標示資料時間（「資料截至 8/7 收盤」），過期資料不冒充最新 |

### M2 每日盤後解讀

**目標**：每天 18:30 前產出 200–300 字白話摘要——產品的每日核心內容。

**使用者故事**：作為新手，我每天收盤後想用一段白話文了解大盤與法人動向，而不是自己解讀一堆數字；作為使用者，我想回看任意日期。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-2.1 | 每日自動生成並發布 | 18:30 前上線；涵蓋大盤、三大法人 |
| FR-2.2 | 數字 100% 來自真實資料 | 程式代入模板，LLM 不生成數字（M7）；抽驗零錯誤 |
| FR-2.3 | 只解讀現象不給建議 | 建議性字眼出現率 0%（eval 把關）|
| FR-2.4 | 歷史回看 | 任意日期可查 |
| FR-2.5 | 免責常駐 | 每則載明教育用途聲明 |

### M3 術語教室

**目標**：術語出現在哪，就在哪學會——產品的「教育」骨幹。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-3.1 | 術語辭典 | 首發 ≥ 10 詞，可持續擴充 |
| FR-3.2 | 每日摘要內建教學 | 至少 1 個當日數據實際出現的術語 |
| FR-3.3 | 解釋有據可循 | 以辭典為準，LLM 不自行發明定義 |
| FR-3.4 | 就地顯示 | 網頁術語 hover 即顯示，不跳頁 |
| FR-3.5 | 術語頁 | 辭典可瀏覽/搜尋（SEO 與自然流量入口）|

### M4 因子研究室（含法遵 gate）

**目標**：提供「怎麼算的看得見、歷史統計誠實揭露」的因子研究。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-4.1 | 因子計算與展示 | 技術指標 + 籌碼因子，數據與計算方式公開 |
| FR-4.2 | 因子貢獻可解釋 | 分數附各因子貢獻明細，加總可驗算 |
| FR-4.3 | 回測誠實呈現 | 勝率、視窗穩定度、vs 大盤、最大回撤 +「歷史不代表未來」每次顯示 |
| FR-4.4 | **分級標籤 feature flag** | 「偏多/偏空」標籤預設對 client 關閉；法遵評估通過才開。關閉時只展示因子數據與統計 |
| FR-4.5 | 未過回測不出現 | 未通過 walk-forward 的規則不進任何 client 可見輸出 |

### M5 個股問答助手

**目標**：自然語言問個股，agent 自查資料、附出處回答。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-5.1 | 個股問答 | 自主選工具取數；數字與工具回傳一致（trace 比對）|
| FR-5.2 | 引用溯源 | 新聞引用附標題/日期/連結且真實存在 |
| FR-5.3 | 拒答邊界 | 買賣建議類 100% 觸發拒絕模板 |
| FR-5.4 | 過程透明 | 工具呼叫過程可展開查看（trace 側欄）|
| FR-5.5 | 誠實查無 | 檢索不到就說查無，不補腦 |
| FR-5.6 | 用量保護 | 每使用者每日提問上限（成本控制），超限友善提示 |

### M6 Web App

**目標**：產品主介面；桌面優先、行動可用。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-6.1 | 今日摘要頁（首頁）| 走勢圖 + 法人柱狀 + 摘要 + 術語 tooltip + 日期回看；未登入可看（獲客入口）|
| FR-6.2 | 個股頁 | K 線疊 MA + 因子數據 + 回測統計（分級標籤受 FR-4.4 gate）|
| FR-6.3 | 對話頁 | 訊息串 + 引用可點 + trace 側欄（登入後可用，FR-5.6 限額）|
| FR-6.4 | 品質頁 | eval pass rate 與失敗案例公開（M7 可視化，信任賣點）|
| FR-6.5 | 免責常駐 | 每頁 footer + 內容內，文案後端統一下發 |

### M7 信任機制（橫切）

**目標**：「這個產品知道自己哪裡不可信」——相對一般 AI 產品的核心差異，也是法遵的技術防線。

| # | 需求 | 落在 | 驗收標準 |
| --- | --- | --- | --- |
| FR-7.1 | 數字防幻覺 | M2/M5 | 數字由程式代入或工具回傳，LLM 不生成 |
| FR-7.2 | 輸出忠實度驗證 | M2 | eval set ≥ 20 組；改 prompt 必重跑；低於門檻擋上線 |
| FR-7.3 | 引用溯源 | M5 | 無法溯源的事實句視為缺陷 |
| FR-7.4 | 建議黑名單 | M2/M5 | 建議性字眼出現率 0%，上線前自動掃描 |
| FR-7.5 | 品質公開 | M6 | eval 歷史對 client 公開 |
| FR-7.6 | 免責與定位 | 全部 | 所有輸出載明教育用途 |

### M8 帳號與自選股（待規劃 → 工程 phase 5）

**目標**：記住使用者、個人化內容——留存的地基。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-8.1 | 註冊/登入 | Email magic link 或 OAuth（Google），不自管密碼 |
| FR-8.2 | 自選股清單 | 加入/移除個股；摘要與晨報優先呈現自選股 |
| FR-8.3 | 個人化摘要 | 每日摘要附「你的自選股」段落（同樣走 M7 防線）|
| FR-8.4 | 資料最小化 | 只收 email；可自行刪除帳號與資料 |

### M9 每日晨報推播（待規劃 → 工程 phase 5）

**目標**：內容主動送達——不依賴使用者記得打開網站。

| # | 需求 | 驗收標準 |
| --- | --- | --- |
| FR-9.1 | 每日 email 晨報 | 開盤前送達（如 08:00）；含昨日摘要 + 自選股數據 + 1 個術語 |
| FR-9.2 | 訂閱管理 | 一鍵退訂；退訂即停 |
| FR-9.3 | 通道可擴充 | 先 email，LINE Notify 列為後續 |
| FR-9.4 | 內容同紀律 | 晨報內容過同一套 M7 防線與免責 |

## 6. 成功指標

| 階段 | 指標 | 目標 |
| --- | --- | --- |
| MVP 驗證 | 自己 + 5–10 名種子使用者連續 2 週每天打開 | 內容價值的最誠實驗證 |
| 產品健康 | 摘要準時發布率 | ≥ 99%（18:30 前）|
| 信任（不可妥協）| 數字錯誤 / 建議性字眼 | = 0（eval + 上線前掃描）|
| 留存 | 晨報開信率 / 週回訪 | 上線後建 baseline 再訂目標 |
| 成本 | LLM 成本/使用者/月 | 有量測，問答限額可調 |
