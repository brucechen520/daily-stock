## 量化 / 訊號

### 回測（原 Phase 2'）

單因子（外資連買天數）+ 固定參數 + walk-forward 跑通一輪。完整規格見 [phase-2.md](phase-2.md)。

- **暫緩理由**：北極星改為自用工具後，最痛的需求是「我手上這幾檔今天怎麼了」，而回測解決的是「這個規則歷史上有沒有用」——後者是研究需求，不是每日需求。而且 phase-2 文件自己 timebox 一週，實際會吃掉 Phase 1.5 的全部預算。
- **重啟條件**：Phase 1.5 驗收通過（連續 5 個交易日真的在讀）且想開始回答「這些統計數字到底有沒有預測力」時。
- **紅線提醒**：在回測完成前，**任何輸出都不得出現方向性訊號或分級標籤**（ROADMAP 原則 4）。Phase 1.5 全部是描述性統計，不觸此線。

### 回測完整版（原 2''）

多因子、調參、交易成本模型、survivorship 處理。

- **暫緩理由**：學習目標是 AI 應用，量化深度優先序最低。
- **重啟條件**：求職敘事需要衝量化深度時。

## 推播 / 介面

### Discord embed 卡片

有欄位、顏色、可依漲跌上色。

- **暫緩理由**：純文字 webhook 半天可完成且 code block 能對齊表格；embed 是外觀升級，不改變資訊量。
- **重啟條件**：純文字讀起來真的很痛時（例如 20 檔對齊在手機上跑版）。

### Discord bot（斜線指令互動）

`/stock 2330` 隨時查任一檔。

- **暫緩理由**：需要 bot token、權限管理、長駐連線，而 webhook 只需一個 URL。單向推播已滿足每日需求。
- **重啟條件**：要做「任意個股查詢」時——那時 bot 才有意義（見下）。

### 任意個股查詢

不限 watchlist，隨時 `daily-stock stock 2330` 查歷史與指標。

- **暫緩理由**：是 watchlist 追蹤的免費副產品（同一批查詢加個 flag），但沒有 backfill 過的個股資料是空的，實用性受限。
- **重啟條件**：Phase 1.5 完成後隨時可加，成本低。

### Web dashboard（原 Phase 4）

Go API（REST + SSE）+ React/TS 前端四頁。

- **暫緩理由**：單一使用者情境下，網頁的價值遠低於推播（推播會主動找上你，網頁要你記得打開），成本卻高一個量級。
- **重啟條件**：北極星第 2 順位（對外產品）啟動時，或推播的資訊密度真的不夠用時。
- **設計預留**：`render` / `sender` 已分層，改網頁時 `render` 可直接復用。

### Email 通道

- **暫緩理由**：Discord 手機推播的到達率遠高於 email（email 會沉進廣告信裡），而自用工具的頭號死因就是「忘記打開」。
- **重啟條件**：若實際使用後發現 Discord 通知會被自己忽略。

## 資料 / 正確性

### `positions` 逐筆交易表

逐筆買進賣出紀錄，均價由程式計算。

- **暫緩理由**：完整持倉管理要處理賣出、部分出場、除權息還原後的成本調整，是個坑。目前 `watchlist` 的單一 `avg_cost` 是它的子集。
- **重啟條件**：開始分批加碼／攤平，手動維護 `avg_cost` 變得容易出錯時。
- **升級路徑**：加 `positions` 表後把 `watchlist.avg_cost` 改成 view，既有資料不作廢。

### 減資 / 增資的價格還原

- **暫緩理由**：不在 `TWT49U` 表內，需另找資料源；台股減資增資相對罕見。
- **重啟條件**：watchlist 中有個股實際發生減資／增資時。
- **暫時處理**：發生時該檔標記「本期有公司行動，歷史數字未還原」。

### 配股（股票股利）計入總報酬

- **暫緩理由**：`TWT49U` 的「權值+息值」是合計值，拆解配股需額外資料源。
- **重啟條件**：watchlist 中有配股比例高的持股時。
- **暫時處理**：總報酬只計現金部分，欄位旁標「含配股，未計入股票股利」。

### `adj_close` 查詢 cache 優化

- **暫緩理由**：目前只有 20 檔 × 12 個月，物化欄位已足夠。
- **重啟條件**：股票池擴大到全市場或歷史拉到數年，重算成本變高時。

## LLM / AI

### 新聞 RAG + 問答 agent（原 Phase 3）

新聞 embedding（pgvector）+ hybrid 檢索 + tool-use agent + agent eval。

- **暫緩理由**：順序不變，仍是 AI 練習主菜，只是排在 Phase 1.5 之後。
- **重啟條件**：Phase 1.5 驗收通過後直接接上。
- **相依**：以下兩項要等它做完才能開。

### 讓 LLM 讀新聞並做因果解讀

- **暫緩理由**：新聞一進 prompt，LLM 就會編出讀起來合理、卻無法用 eval 驗證的因果句（「因為法說會樂觀所以外資買超」），對持有人的決策影響極大。詳見 [phase-1.5.md](phase-1.5.md) §5.3。
- **重啟條件**：Phase 3 的 RAG 引用溯源機制完成後——有出處可驗證時才開。

### 每則新聞加 LLM 一句摘要

- **暫緩理由**：每天約 40 次額外 LLM 呼叫，而台媒 RSS 標題本身已極度直白，摘要邊際價值接近零。
- **重啟條件**：改用標題不具資訊量的新聞源時。

### LLM 分類新聞關聯個股

取代股名字串比對。

- **暫緩理由**：成本隨新聞量線性上升（每 30 分鐘抓一次）。
- **重啟條件**：Phase 3 有 embedding 後，用向量相似度取代，不必逐則問 LLM。
